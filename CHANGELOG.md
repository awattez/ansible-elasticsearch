# Changelog

## 1.0.0

First release of the `awattez.elastic` collection, forked from the archived
[elastic/ansible-elasticsearch](https://github.com/elastic/ansible-elasticsearch)
role (last upstream release: 7.17.x). The `main` branch mirrors upstream
untouched; everything below lives on `next`.

### Merged from other forks

- [hostinger/ansible-elasticsearch](https://github.com/hostinger/ansible-elasticsearch) -
  starting tree: 8.x support, FQCN modules, Molecule tests, systemd-only cleanup
- [philbudne/ansible-elasticsearch](https://github.com/philbudne/ansible-elasticsearch) -
  auto-generated CA + per-node certificates, ported and parameterized
  (`es_certificates`)

### Added

- Collection packaging: `galaxy.yml`, `meta/runtime.yml`, roles
  `elasticsearch` and `kibana`
- Batteries-included playbooks - naming convention: roles = components
  (nouns), playbooks = operations: `all`, `elasticsearch`, `kibana` - a
  scenario is a single inventory file. Reserved names for later:
  `logstash`, `upgrade_*`
- `kibana` role: official repo, package, `kibana.yml` rendered from the
  `kibana_config` dict, systemd service, wait-for-ready
- Computed defaults from the inventory: `node.name`, `cluster.name`,
  `network.host: 0.0.0.0`, `discovery.type: single-node` (1 host in
  `es_cluster_group`) or `discovery.seed_hosts` +
  `cluster.initial_master_nodes` (2+ hosts)
- Self-signed CA + per-node certificates generated by default
  (`elasticsearch-certutil`) when TLS is enabled without `es_ssl_*` material
- `es_user_passwords`: user → password map applied through the security API
  (built-in users like `kibana_system` included)
- Encrypted PEM keys via `es_ssl_key_passphrase`, stored as
  `secure_key_passphrase` in the Elasticsearch keystore
- Early explicit failure on insecure multi-node layouts (the 9.x transport
  TLS contract) instead of cryptic bootstrap-check errors
- `GUIDE.md` step-by-step walkthrough; ansible-lint + Molecule (default,
  security, custom-config) in GitHub Actions

### Changed

- Targets Elasticsearch/Kibana 9.x (default `9.5.2`), ansible-core 2.16+
- Package installs only: official APT/YUM repos (keyring under
  `/usr/share/keyrings`, no deprecated `apt-key`) or direct package URL
- Security-first: security on by default, `elastic` password seeded via
  `bootstrap.password` in the Elasticsearch keystore
- JVM heap through a `jvm.options.d/heap.options` drop-in instead of a
  templated `jvm.options`
- TLS material is PEM only

### Removed

- SysV init support (systemd only), multi-instance per host, OSS packages,
  6.x/7.x migration paths, Java installation, index template management
- `es_users`/`es_roles` file + native realm machinery and the custom Python
  filter plugins - creating users/roles is a Kibana/API concern
- PKCS12 keystore/truststore support
- Uninstall playbook - tear down by deleting/recycling the VMs
- Kitchen/Ruby test harness, Jenkins `.ci/` jobs, `Makefile`, `Gemfile`,
  `ansible.cfg`
