# awattez.elastic (Ansible collection, 9.x fork)

Deploy and operate **Elasticsearch 9.x** on Debian/Ubuntu and RHEL-family
hosts, from the official Elastic packages.

Fork of the archived
[elastic/ansible-elasticsearch](https://github.com/elastic/ansible-elasticsearch)
role, modernized, trimmed down and **repackaged as a collection with embedded
playbooks**: your scenario is a single inventory file, the
playbook ships with the collection:

```bash
ansible-playbook -i inventory.yml awattez.elastic.all
```

**New here? Follow the step-by-step [GUIDE.md](GUIDE.md)** - from an empty
directory to a running (single-node or 3-node TLS) cluster.

## Lineage

| Source | What it provided |
|---|---|
| [elastic/ansible-elasticsearch](https://github.com/elastic/ansible-elasticsearch) (upstream, archived at 7.17.x) | Original role - mirrored untouched on the `main` branch |
| [hostinger/ansible-elasticsearch](https://github.com/hostinger/ansible-elasticsearch) | Starting tree for `next`: 8.x support, FQCN modules, Molecule tests, systemd-only cleanup |
| [philbudne/ansible-elasticsearch](https://github.com/philbudne/ansible-elasticsearch) | `es_certificates: true` - auto-generated CA + per-node certs (ported and parameterized) |
| this repo (`next`, default branch) | 9.x modernization: collection packaging, embedded playbooks, repo keyring, `jvm.options.d`, security-first defaults, legacy purge |

## What changed vs upstream

| | upstream (archived) | this fork (`next`) |
|---|---|---|
| Packaging | standalone role | collection `awattez.elastic` with embedded playbooks (`all`, per component) |
| Elasticsearch | 7.17 | 9.x (default `9.5.2`) |
| Kibana | separate archived role | included `kibana` role, deployed via the `kibana` inventory group |
| Discovery | manual `es_config` | computed from the inventory group (single-node vs seed_hosts + initial_master_nodes) |
| Security | opt-in | on by default, `bootstrap.password` seeded via keystore |
| Users/roles | full file + native realm management | `es_user_passwords` - one API call per password; users/roles live in Kibana/API |
| TLS | manual PEM/PKCS12 | PEM (encrypted key supported); no material given → self-signed CA + per-node certs generated by default (`elasticsearch-certutil`) |
| JVM heap | templated `jvm.options` | drop-in `jvm.options.d/heap.options` |
| APT key | `apt-key` (deprecated) | keyring in `/usr/share/keyrings` |
| Init systems | SysV + systemd | systemd only |
| Multi-instance per host | yes | removed |
| OSS packages, 6.x migration paths, Java install | yes | removed |
| Index templates management | yes | removed (use the [elasticstack](https://registry.terraform.io/providers/elastic/elasticstack/latest) provider or the API) |
| Tests | Kitchen/Ruby | Molecule + ansible-lint (GitHub Actions) |

Not supported (yet): installation from a `tar.gz` archive - package installs
only (APT/YUM repository or direct `.deb`/`.rpm` URL).

Full details of what was merged, added, changed and removed:
[CHANGELOG.md](CHANGELOG.md).

## Requirements

- Elasticsearch/Kibana **9.x** (what CI tests). 8.x should work - the
  mechanics are identical since 8.0 (`node.roles`, security on by default,
  transport TLS contract, `jvm.options.d`) - but it is untested here.
  **Not compatible with 6.x/7.x.**
- ansible-core **2.16+**
- Target hosts: Ubuntu 22.04+/Debian 12+ or RHEL/Rocky/Alma 8+, systemd,
  x86_64, with a sudo-capable user

## Installation

`requirements.yml`:

```yaml
collections:
  - name: git+https://github.com/awattez/ansible-elasticsearch.git
    type: git
    version: next
```

```bash
ansible-galaxy collection install -r requirements.yml --force
```

## Usage

Put your hosts in an `elasticsearch` inventory group (and optionally a
`kibana` group), carry **all** configuration as inventory vars, and run an
embedded playbook. No local playbook needed.

### Playbooks

Naming convention: **roles are components** (nouns), **playbooks are
operations**. A bare component name deploys/converges that component; other
operations get a verb prefix.

| Playbook | Runs |
|---|---|
| `awattez.elastic.all` | every component whose group is in the inventory (`elasticsearch`, then `kibana`) |
| `awattez.elastic.elasticsearch` | the `elasticsearch` group only |
| `awattez.elastic.kibana` | the `kibana` group only |

Reserved for later, same scheme: `logstash`, `upgrade_elasticsearch`,
`upgrade_kibana`, `upgrade_all` (rolling upgrade orchestration reusing the
same component roles).

### Computed defaults

The role derives sane settings from the inventory - only override them in
`es_config` when you need to:

| Setting | Computed value |
|---|---|
| `node.name` | `inventory_hostname` |
| `cluster.name` | `elasticsearch` |
| `network.host` | `0.0.0.0` (an Ansible-driven install is remote by definition) |
| `discovery.type` | `single-node` when the `es_cluster_group` group has 1 host |
| `discovery.seed_hosts` | the group's `ansible_host` list, when it has 2+ hosts |
| `cluster.initial_master_nodes` | the group's node names, when it has 2+ hosts |
| `xpack.security.http.ssl.enabled` / `...transport...` | follow `es_enable_http_ssl` / `es_enable_transport_ssl` |
| TLS material | self-signed CA + per-node certs generated when TLS is on and no `es_ssl_key`/`es_ssl_certificate` is given |

### Single node (security on, HTTP without TLS)

`inventory.yml`:

```yaml
elasticsearch:
  vars:
    es_version: "9.5.2"
    es_heap_size: 1g
    es_api_basic_auth_username: elastic
    es_api_basic_auth_password: "{{ lookup('env', 'ELASTIC_PASSWORD') }}"
    es_config:
      cluster.name: lab
  hosts:
    es-single:
      ansible_host: 10.0.0.11
      ansible_user: ubuntu
```

```bash
ansible-playbook -i inventory.yml awattez.elastic.all
```

One host in the group, no explicit discovery → the role renders
`discovery.type: single-node` by itself.

Since 9.x security is always on: `es_api_basic_auth_username` /
`es_api_basic_auth_password` are required. The role seeds the `elastic`
password through `bootstrap.password` in the Elasticsearch keystore before
first start.

### Single node with Kibana

Add the same host to a `kibana` group; the deploy playbook sets the
`kibana_system` password through the security API, then installs Kibana
against it:

```yaml
elasticsearch:
  vars:
    es_version: "9.5.2"
    es_heap_size: 1g
    es_api_basic_auth_username: elastic
    es_api_basic_auth_password: "{{ lookup('env', 'ELASTIC_PASSWORD') }}"
    es_user_passwords:
      kibana_system: "{{ lookup('env', 'KIBANA_SYSTEM_PASSWORD') }}"
  hosts:
    es-single: { ansible_host: 10.0.0.11, ansible_user: ubuntu }

kibana:
  vars:
    kibana_config:
      elasticsearch.username: kibana_system
      elasticsearch.password: "{{ lookup('env', 'KIBANA_SYSTEM_PASSWORD') }}"
  hosts:
    es-single: { ansible_host: 10.0.0.11, ansible_user: ubuntu }
```

Kibana defaults are computed too: `server.host: 0.0.0.0` and
`elasticsearch.hosts: ["http://localhost:9200"]` (colocated). Log in on
`http://<host>:5601` with `elastic`.

### Multi-node cluster with generated certificates

Enable TLS without providing any material and the role generates a
self-signed CA plus one certificate per node of the `es_cluster_group`
inventory group (with `elasticsearch-certutil` on the first node), then
distributes them - that is `es_certificates`, on by default in this case:

```yaml
elasticsearch:
  vars:
    es_version: "9.5.2"
    es_heap_size: 2g
    es_api_basic_auth_username: elastic
    es_api_basic_auth_password: "{{ lookup('env', 'ELASTIC_PASSWORD') }}"
    es_enable_transport_ssl: true
    es_enable_http_ssl: true
    es_config:
      cluster.name: prod
      node.roles: [master, data, ingest]
  hosts:
    es-1: { ansible_host: 10.0.0.11, ansible_user: ubuntu }
    es-2: { ansible_host: 10.0.0.12, ansible_user: ubuntu }
    es-3: { ansible_host: 10.0.0.13, ansible_user: ubuntu }
```

Three hosts in the group → `discovery.seed_hosts` (the IPs) and
`cluster.initial_master_nodes` (the node names) are rendered automatically.

### Multi-node cluster with your own certificates (PEM)

Providing a key + certificate turns the generation off:

```yaml
    es_enable_transport_ssl: true
    es_enable_http_ssl: true
    es_ssl_certificate_authority: "{{ inventory_dir }}/certs/ca.crt"
    es_ssl_certificate: "{{ inventory_dir }}/certs/{{ inventory_hostname }}.crt"
    es_ssl_key: "{{ inventory_dir }}/certs/{{ inventory_hostname }}.key"
    # es_ssl_key_passphrase: "{{ vault_key_passphrase }}"   # if the key is encrypted
```

PEM only - no PKCS12. Encrypted keys are supported: the passphrase lands in
the Elasticsearch keystore as `xpack.security.<layer>.ssl.secure_key_passphrase`.

### User passwords

```yaml
    es_user_passwords:
      kibana_system: "{{ vault_kibana_system }}"
      logstash_system: "{{ vault_logstash_system }}"
```

One security API call per entry, on existing users (the built-in ones
included). That covers the provisioning need - service account passwords.
Creating users and roles is deliberately out of scope: do it in Kibana or
through the API.

### Plugins, license, keystore entries

```yaml
    es_plugins:
      - plugin: analysis-icu
    es_xpack_trial: true                       # or es_xpack_license: "{{ lookup('file', 'license.json') }}"
    es_keystore_entries:
      - key: s3.client.default.access_key
        value: "{{ vault_s3_access_key }}"
        state: present
```

There is deliberately no uninstall playbook: tear down by deleting or
recycling the VMs.

## Main variables

See [`roles/elasticsearch/defaults/main.yml`](roles/elasticsearch/defaults/main.yml)
for the full commented list.

| Variable | Default | Purpose |
|---|---|---|
| `es_version` | `9.5.2` | Exact package version |
| `es_use_repository` | `true` | Official APT/YUM repo (`false` + `es_custom_package_url` for a direct package) |
| `es_version_lock` | `false` | Hold/versionlock the package |
| `es_heap_size` | unset (auto) | Xms/Xmx via `jvm.options.d/heap.options` |
| `es_config` | `{}` | Rendered as-is into `elasticsearch.yml` - any ES setting |
| `es_api_basic_auth_username` / `..._password` | - | Required; used for bootstrap + API operations |
| `es_enable_http_ssl` / `es_enable_transport_ssl` | `false` | Enable TLS per layer |
| `es_certificates` | auto | Generate self-signed CA + per-node certs; defaults to `true` when TLS is on and no `es_ssl_key`/`es_ssl_certificate` is given |
| `es_ssl_key` / `es_ssl_certificate` / `es_ssl_certificate_authority` | `""` | BYO PEM material |
| `es_ssl_key_passphrase` | `""` | Passphrase of an encrypted PEM key (stored as `secure_key_passphrase` in the ES keystore) |
| `es_cluster_group` | `elasticsearch` | Inventory group used for cert generation and computed discovery |
| `es_user_passwords` | `{}` | user → password map, applied via the security API (`elastic` superuser always exists) |
| `es_plugins` | - | Plugin list (idempotent add/remove) |
| `kibana_config` | `{}` | Rendered as-is into `kibana.yml` - any Kibana setting (kibana role) |

## Testing

```bash
pip install -r requirements.txt
ansible-lint
ansible-galaxy collection install . --force
molecule test -s default        # single node, security off
molecule test -s security       # TLS http+transport, BYO certs
molecule test -s custom-config  # heap, plugins, keystore, log4j2
```

CI runs the same on every push/PR to `next`.
